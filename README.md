# scout.edgelab.one

The public static site of Scout: a landing page at `/` and the learning center at `/learn/` (lessons, practice paths,
concept keys and the topic modules that group the lessons). Plain HTML built from JSON by one Python script, no JavaScript
framework, no tracking, hosted on Cloudflare Pages. The design is in the orchestrator repository, `docs/learning-center/deploy.md`.

## Layout

```
content/      the library, the only input: keys/, lessons/, practice/, modules/ (13 topic modules and index.json), scenarios/ (simulator),
              sim-staging/ (sim fields of lessons not in this tree yet), redirects.json (empty), changelog.json, site.json, merge-candidates.json
assets/       the shipped course assets (course.css, course.js, theme-init.js, mermaid/, hljs/), site-extra.css, search.js, favicon.svg,
              sim/ (the built simulator: sim.js, engine.js, sim.css, LICENSE.txt, UPSTREAM.txt; committed)
src/sim/      the simulator block in vanilla TypeScript (core.ts shared with the headless runner, block.ts the page block)
vendor/breakscale/   the pinned, MIT-licensed engine subset (12 files, LICENSE, UPSTREAM.txt hashes, PATCHES.md)
static/       robots.txt and _headers, copied verbatim into site/
tools/        import_course.py  --module ID --export DIR: import a pipeline course's export into one module of content/ (never imports gigai)
              seed_content.py   retired (refuses to run; it was the one-off seed of site 2026.10.1)
              export_catalog.py content/ -> the library catalog scout-learning-catalog:3, validated against catalog3.schema.json
              scan.py           the public-material scan and the schema check of content/; with --built, the no-tracking grep over site/
              build.py          content/ -> site/ (standard library only), with the link audit, glyph check and size caps
              serve_check.py    serves site/ on 127.0.0.1 with the exact headers of _headers
              chrome_check.py   headless Chrome over the DevTools pipe: console errors, CSP violations, hosts, screenshots, Pagefind proof
              chrome_cli.sh     the plain command-line Chrome runs (--screenshot, --dump-dom, 390 px iframe wrapper)
              sim/              check.sh, build.sh, check_vendor.py, golden.mjs, the node tests and golden/ (see "The simulator")
              test_practice_kinds.py  case and artifact pages, the one-module rule and the catalog export, on a temp copy of content/
              test_sim_pages.py the simulator's scan rules (negative tests for the digit rule) and page rendering
verify/       screenshots, logs and summaries of the last browser verification
site/         build output, git-ignored
```

## Build locally

```sh
python3 tools/scan.py                       # content: public-material scan + schema check (exit 1 on any hit)
python3 tools/build.py                      # content/ -> site/
python3 tools/export_catalog.py /tmp/catalog.json   # the library catalog (CI runs this once as a check)
npx -y pagefind@1.5.2 --site site --glob "learn/**/*.html" --output-path site/learn/pagefind    # the search index
python3 tools/scan.py --built site          # no foreign resources, no trackers in the built HTML
lychee --offline --include-fragments --index-files index.html --root-dir "$PWD/site" --no-progress 'site/**/*.html'   # internal links
python3 tools/serve_check.py                # http://127.0.0.1:18765/ with the production headers
python3 tools/chrome_check.py               # browser verification into verify/
```

Pagefind indexes only `learn/**` (the landing, the changelog, the search page and the 404 are out) and writes its bundle to
`site/learn/pagefind/`. It needs `script-src 'wasm-unsafe-eval'` and `worker-src 'self' blob:`, both in `static/_headers`.

## The public-material rule

Everything in this repository is public. Nothing in `content/` may hold a job-posting sentence, a company tied to a posting, a count of
postings, anything of a resume, or anything shaped like a master id. `tools/scan.py` runs the data-free checks (forbidden keys at any
depth, the master-id shape, the posting-count sentence pattern, https-only addresses) on every push. The full scan against postings
and a resume happens on the maintainer's machine when a course is exported from GigAI, never here.

## The attribution rule

Every page's footer says the lessons and practice paths were generated by Claude through GigAI. Every lesson and practice page says
"Generated by Claude through GigAI on <date>" under its title, from `provenance.generated_on`, and adds "reviewed by a person on
<date>" only when `provenance.reviewed_by` and `provenance.reviewed_on` are both set. The build refuses an empty `generated_by` and a
reviewer without a date.

## Modules

The site holds topic modules only: `content/modules/<id>.json` (schema `learning-center-module:2`: `id, version, title, status, summary`,
optional `intro`, optional `parts`, `lessons[{id, status, ...}]`, `changelog`) and `content/modules/index.json` (the order, and per module
the title, status, summary and the published and planned counts). A module's `lessons` are its teaching order. **Every published lesson
sits in exactly one module**, and an entry's id must be a lesson file (`published`) or have none (`planned`, with a `title`); there are no
cross-references and no `home`, `why` or `depth` fields. `tools/scan.py` enforces all of it, and that every module file is listed in the
index once with matching counts. The 12 topic modules have published entries only, an `intro` and a `summary`; `system-design` has
`parts` A to D and nine planned entries.

Pages: `/learn/` (13 module cards and the search box), `/learn/modules/` (the index of all modules), `/learn/modules/<id>/` (summary,
intro, lessons in order with Practice links, changes). A lesson's breadcrumb is Learning center > module > lesson (a practice page's adds the
lesson) and its sidebar lists its module's lessons. `/learn/keys/<key>/` lists the lessons with that concept and the module of each.
Lesson URLs are unchanged.

## Removed: role pathways and families

The two role pathways (MLOps / ML platform engineer, AI forward deployed engineer) and the role families are gone: no `content/pathways/`,
no `content/families/`, no pathway or family schema, renderer or page, no role tables (expectations, technologies), no redirects and no
stub pages. The old `/learn/pathways/` and `/learn/families/` URLs simply stop existing. The per-role sequence is built by Scout on the
user's own machine from the library catalog; the site only publishes the modules and lessons.

## The library catalog (export)

`python3 tools/export_catalog.py OUT.json` writes one file, `scout-learning-catalog:3`, from `content/`: the modules in index order with
their published lessons in module order; per lesson its id, title, module, concept keys (primary first), subtopic ids and titles,
`has_practice` and `practice_kind`; the shared concept keys with display, area, category, technical flag and aliases; the `site` block
(`base_url`, `site_version`, `lessons_path`, `practice_path`, `modules_path`); and `catalog_version` (`<site_version>+keys<n>`). No role, no
sequence, no expectations or technologies, no posting counts, no text bodies. It is validated against `tools/catalog3.schema.json` before
it is written and refuses to write when `scan.py` has problems. gigai keeps its own copy of the file; the site's CI only runs the export
once as a check and keeps nothing.

## Adding a module

Write `content/modules/<id>.json` with planned entries (each with a `title`) and a row in `modules/index.json`; run gigai's generator for it
on the maintainer's machine, export, then `python3 tools/import_course.py --module <id> --export <dir>`. `tools/import_course.py` maps every
concept id of the export to a key of `content/keys/concept-keys.json` (an unknown id is refused), writes lessons and practice paths, flips
the module's entries to `published` and updates its index row; it refuses an id the module does not list and a lesson file that exists
unless `--replace`. A content change must bump the version of the lesson or module it touches and add a changelog line.

A practice file has a `kind`: `tool` (the default, steps cited into a tool's documentation), `case` or `artifact` (written pages with no source;
`tools/test_practice_kinds.py` imports two synthetic fixtures from `tools/fixtures/` into a temp copy of `content/` and builds them).

## The simulator

A lesson or design exercise may carry a `sim` field (scenario id, heading, caption, steps, `sim_claims`). `tools/build.py` renders it as a
heading, the caption, the steps and `<div class="sim" data-scenario="/learn/scenarios/<id>.json" data-pagefind-ignore>`, links
`/_assets/sim/sim.css` and loads the one module `/_assets/sim/sim.js` (same origin, no inline script). The block fetches the scenario
JSON (the only request it makes), runs the engine in the page and draws it: an SVG picture with moving request dots, queue bars and
"saturated" / "busy" / "crashed" badges, a canvas chart, text readouts, labelled range knobs, a crash button where the scenario has a fault,
Pause and Reset. Under `prefers-reduced-motion` there is no animation loop: the model steps once a second and the dots are hidden.

- **Scenario files**: `content/scenarios/<id>.json`, format `learning-center-sim:1` (nodes with all nine base config fields, edges, 1 to 3
  knobs, optional `faults`, `readouts`, `assertions`). `scan.py` validates them. The build copies them to `site/learn/scenarios/`.
- **Golden runs**: `node tools/sim/golden.mjs --write [id]` runs every scenario headless on the built `assets/sim/engine.js` (warm-up, then one
  sample a second over the window) and writes `tools/sim/golden/<id>.json`: a `defaults` row and one row per assertion with all metrics
  and the verdict. Commit it with the scenario; `--check` fails on any difference.
- **The digit rule**: every number or quantity word ("quarter", "half", "double", "ten times") in a sim caption or step must sit inside a
  `sim_claims[].text` whose assertion passes in the golden file and whose numbers that golden row shows (rounded, or as a percentage); a knob
  setting is an instruction and needs no claim. `scan.py` refuses anything else (`tools/test_sim_pages.py` proves it). A stale golden file
  (scenario changed since) is refused too.
- **Goodput and offered** are 5-second means over the same window, and the goodput shown is capped at offered, so a reader cannot see goodput above the load offered.
- **Build**: `sh tools/sim/build.sh` (pinned `npx -y esbuild@0.28.2`, banner with the MIT notice) writes `assets/sim/sim.js` and `engine.js`;
  both are committed so the site builds without node. `engine.js` is for the headless runner only and is not copied into the site.
- **Checks** (also the first step of the CI check job): `sh tools/sim/check.sh` = vendor hashes (`check_vendor.py`), committed build equals a
  fresh build, `node --test` (closed forms M/M/1, M/M/4, Kingman, Little; conservation and bounds on every scenario) and the golden runs
  against the committed files. No type check runs (it needs a package fetch); esbuild strips types.
- **Third-party code**: the engine is Breakscale (https://github.com/xevrion/breakscale, MIT, commit d2c876e0): 12 files copied byte for byte
  into `vendor/breakscale/` with their licence, plus one recorded one-line patch (`PATCHES.md`: the percentile sample cap 512 to 4096). Its
  interface, analytics and link store are not included. A re-pin is a copy, a re-applied patch, new hashes and a golden re-run.
- **Browser proof**: `python3 tools/chrome_check.py --sim --out DIR` (against `serve_check.py`) checks the simulator pages at 1280 and 390 px and
  with reduced motion; screenshots land in `DIR/shots/sim-*.png` (copied to `verify/shots/`).
